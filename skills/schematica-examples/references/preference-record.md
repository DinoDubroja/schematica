# Visual preference record

Procedure for an approved general preference. Follow [chat behavior](../../../agents/BEHAVIOR.md)
for discussion/approval and [project rules](../../../agents/PROJECT_RULES.md) for
authoritative homes, hierarchy, README markers, generation, and validation.

1. Read [GENERAL.md](../../../preferences/GENERAL.md) and matching accepted/pending
   entries. Reuse a matching ID. Confirm whether the lesson is general, style-specific,
   or local; keep style exceptions and local feedback in their established records.
2. Create/update the independent rule's `RULE.md` with stable ID, status, date, exact
   instruction, scope/exclusions, evidence, and provenance. Link shared precedence.
   Separate approval of the rule from review of its new illustrations. Preserve the
   decision trail and superseded IDs/wording when splitting an existing rule.
3. Prepare its short `README.md` visual section: required Good, optional Bad, useful
   caption, source/download links. Use authorized supplied images, selected generated
   revisions, or a clearly recorded focused reconstruction. Do not invent historical
   screenshots. Isolate the judged feature and match scale across a comparison.
4. Keep editable source and matching transparent light/dark SVGs and PNG downloads.
   Follow [PRESENTATION.md](../../../scripts/PRESENTATION.md); render derivatives from
   source rather than editing them independently. Link supporting example records
   instead of copying entire source circuits into every rule folder.
5. Update the accepted index and inactive queue with the actual decision; choose or
   retain the appropriate category and representative. Rebuild galleries using the
   [documented command](../../../agents/PROJECT_RULES.md#deterministic-gallery-generation).
6. Read back the rule/evidence, inspect the illustrations, verify source/export
   agreement, both themes, navigation, inheritance, and `--check`. Preserve concurrent
   work and finish the scoped context update, commit and push per project rules.
